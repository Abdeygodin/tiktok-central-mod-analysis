# Разбор «TikTok Central MOD» (v43.6.5 / v47.1.7 / v48.0.5)

Статический и динамический разбор популярного мода TikTok, который распространяется через Telegram и сайты-агрегаторы APK. Цель — понять, что именно добавлено в приложение поверх оригинального TikTok, куда оно ходит в сеть и есть ли там что-то опасное.

> В репозитории **нет APK, нет инструментов для пересборки и нет ключей подписи** — только описание, хеши и индикаторы. Разбор сделан на собственном устройстве в исследовательских целях.

## Коротко

- Явного вредоносного поведения (кража аккаунтов, SMS, контактов, cookies, загрузка и запуск стороннего кода) **не обнаружено** в той части кода, которую удалось прочитать.
- Мод — это **четыре слоя чужого кода** поверх TikTok от разных авторов, плюс перепаковка сайтом LiteAPKs.
- Все слои регулярно **ходят на серверы авторов** за рекламой, «новостями» и «обновлениями». Кнопка «обновить» ведёт на сторонние сайты, откуда можно получить любой APK.
- Значительная часть кода **спрятана в нативные библиотеки** (Dex2C) и в **виртуальную машину байткода** — прочитать её целиком невозможно, поэтому «чистым» мод назвать нельзя.
- Обход региональных ограничений работает через **подмену данных SIM-карты** внутри приложения (по умолчанию — Беларусь, МТС).

Кроме этого в коде есть ссылки на Telegram-каналы и соцсети авторов — это просто открываемые ссылки.

**Плашка LiteAPKs и `update.9mod.com` (разобрано в ноябре 2026).** Устройство оказалось не таким, как выглядит: в APK нет ни адреса, ни версии `48.0.7`.

- Апдейтер целиком — класс `īi.ïi.pk$100000008` (`classes28.dex`), у него **единственный нативный метод `run()`**; в нём собирается адрес, выполняется запрос и строится диалог.
- `update.9mod.com` в строках отсутствует — он формируется в машинном коде `libieuwh.so`. Поэтому замена `liteapks.com`, `afmod.com` и заголовка `9MOD.COM` (они лежат в массивах `float`) плашку не убирает.
- Кэша нет: при каждом запуске приложение заново получает версию с сервера и показывает плашку, если сервер считает её новой. Поднять `versionCode`/`versionName` установленного приложения тоже не помогает — проверено на устройстве.
- Отсюда же следует, что в авиарежиме плашки нет: без успешного запроса диалог не показывается.

**Как убрать надёжно.** Блокировка `update.9mod.com` и `9mod.com` на уровне DNS — рабочий обход, но он держится на том, что фильтр действительно стоит (частный DNS, VPN или hosts с root). Гарантированно убирает плашку правка нативного кода: первая инструкция `run()` по смещению `0x8e3a4` в `lib/arm64-v8a/libieuwh.so` меняется с `fd7bbaa9` (`stp x29, x30, [sp, #-0x60]!`) на `c0035fd6` (`ret`). Поток обновления запускается и сразу завершается, остальной мод не затрагивается. Проверено на устройстве: три холодных старта — ни запроса, ни диалога, ни падений.

Главный риск здесь не в текущем содержимом серверов, а в том, что **авторы в любой момент могут поменять ссылку «обновления»** — и пользователь сам установит то, что ему подсунут.

## Как работает обход региональных ограничений

TikTok определяет страну пользователя в основном по данным, которые сообщает само приложение: страна SIM, код и название оператора, регион системы. Мод подменяет их внутри приложения, поэтому работает без VPN.

1. Значения хранятся в настройках плагина; если плагин не настроен, используются значения по умолчанию из `com.tiktok.plugin.client.ClientSettings$Region`:

   | Ключ | По умолчанию | Смысл |
   |---|---|---|
   | `country` | `Belarus` | страна |
   | `iso` | `by` | ISO-код страны SIM |
   | `mcc` | `257` | Mobile Country Code (Беларусь) |
   | `mnc` | `002` | Mobile Network Code (МТС Беларусь) |
   | `operator` | `MTS` | название оператора |
   | `forceRegion` | `false` | показывать только контент выбранного региона |

2. TikTok получает данные SIM через собственные обёртки над `TelephonyManager`. В моде эти обёртки (около десятка мест в `classes17` и `classes29`) переписаны так, что вместо обращения к системе возвращают значения из настроек:
   - `getSimCountryIso` → `ClientSettings$Region.getIso()`
   - `getSimOperator` / `getNetworkOperator` → `getOperator()` (= `mcc + mnc`)
   - `getSimOperatorName` / `getNetworkOperatorName` → `getOperatorName()`

3. Подмена подписи нужна, чтобы проверки целостности TikTok не заметили пересборку.

Итог: на экране входа отображается «account located in Belarus», хотя устройство никогда так не представлялось.

## Как реализованы функции мода

Почти все функции сделаны одним приёмом: в байткод TikTok вставлены вызовы классов мода (около 40 мест), а сама логика этих классов скомпилирована в `libGoldDcc.so`. Видно, *где* мод вмешивается и *что* подменяет; точные условия внутри нативного кода частично скрыты.

### Удаление рекламы

Сервер TikTok продолжает присылать рекламу — мод вырезает её на устройстве.

| Реклама | Место в TikTok | Что делает мод |
|---|---|---|
| Лента «Для вас» | `FeedApiService.fetchFeedList` → `FeedItemsProcess.init(FeedItemList)` сразу после получения ответа; ещё два места → `FeedItemsProcess.feedAds(List, bool)` | Перебирает список видео и удаляет элементы с `Aweme.isAd()` |
| Реклама посреди ленты | `MidAdResponse.getAweme()` | Читает поле `aweme`, но возвращает значение мода (`MidAds.getDefaultAweme`) |
| Рекламная заставка | `FeedApi.LIZIZ` и ещё 4 метода → `SplashAds.getNullValue()` | При `null` пропускается вызов `ISplashAdService`, а загрузчики заставки возвращают `null` |
| Баннеры и тренды в «Поиске» | → `DiscoverProcess.discoverBannerAds(BannerList)`, `discoverTrendingAds(TrendingTopicList)` | Чистят списки |
| Реклама в «Подписках» и профиле | переключатели плагина | — |

Тот же фильтр ленты использует поля `isLive`, `isImage`/`isPhotoMode`, `isStory`, `getDuration`, `getStatistics().getPlayCount/getDiggCount`, `getRegion` — так реализованы «убрать прямые эфиры / слайд-шоу / истории / длинные видео», фильтр по просмотрам и лайкам и режим «Force Region».

### Настройки плагина

Регион; Force Region Mode; Gray mode; Unmute (звук на видео с заблокированной музыкой); удаление водяного знака для видео / фото / GIF; папки скачивания; скачивание без звука; удаление рекламы в ленте, «Подписках», профиле, баннеров и трендов «Поиска»; удаление прямых эфиров, слайд-шоу, историй, длинных видео, подписей; фильтр по просмотрам и лайкам; чёрный список слов в подписях; вкладки «Поиск», «Друзья», «Рядом»; Дуэт и Stitch; скорость и длительность воспроизведения; остановка повтора; «чистый экран»; шрифты.

## Почему нет вкладки Shop

В моде нет ни настройки, ни кода, связанного с магазином: в списке функций плагина и в строках `libGoldDcc.so` нет ничего про shop/mall/e-commerce. Код TikTok Shop в приложении присутствует — вкладку включает сервер.

Проверка на устройстве (аккаунт с выполненным входом): регион в плагине переключён с Беларуси на **Великобританию** (рынок, где TikTok Shop работает), TikTok перезапущен — лента загрузилась, но **вкладка Shop не появилась** (нижняя панель: Home, Friends, +, Inbox, Profile). Затем регион возвращён обратно.

Значит, подмена данных SIM на это не влияет. Наиболее вероятное объяснение — доступность магазина определяется регионом самого аккаунта, который фиксируется при регистрации, а не текущими данными устройства. Это гипотеза: проверить её без другого аккаунта нельзя.

## Разрешения

Набор разрешений совпадает с оригинальным TikTok (камера, микрофон, контакты, геолокация, медиа, Bluetooth, наложение поверх окон и т. п.). Рекламные разрешения (`AD_ID`, `ACCESS_ADSERVICES_*`, Install Referrer) мод отключил переименованием в `disabled_*`.

**Не найдено:** службы специальных возможностей, администратор устройства, доступ к SMS/звонкам, `REQUEST_INSTALL_PACKAGES`, `QUERY_ALL_PACKAGES`, VPN-сервис, слушатель уведомлений. Автозапуск после перезагрузки есть, но принадлежит стандартному `androidx.work`.

## Чего в коде не найдено

В прочитанном коде мода (Java-часть, строки и JNI-обращения нативных библиотек) нет:

- отправки контактов, SMS, истории звонков, списка приложений;
- чтения cookies, токенов сессии или паролей TikTok;
- выполнения shell-команд (`Runtime` используется только для `exit` при перезапуске);
- загрузки и запуска стороннего dex/so-кода (`DexClassLoader` и т. п.);
- доступа к специальным возможностям для перехвата экрана.

## Ограничения разбора

- Нативный код (`libGoldDcc.so`, `libprime.so`) проверялся по строкам, импортам и JNI-обращениям, а не полным дизассемблированием. В `libieuwh.so`, помимо этого, разобрана регистрация нативных методов и функция `run()` обновлятора (см. раздел про плашку). Внутри `libieuwh.so` находится весь `MainActivity` TikTok.
- Код плагина внутри виртуальной машины `libtigrik.so` не дешифровался.
- Телеметрия самого TikTok (ByteDance applog, AppsFlyer, Firebase) никуда не делась — она часть приложения.

Поэтому вывод «вредоносного поведения не обнаружено» относится к проверенной части, а не ко всему коду.

## Рекомендации тем, кто пользуется модом

1. **Не нажимайте «обновить» внутри мода.** Ссылки ведут на сторонние сайты (LiteAPKs, tiktok-apk.com), которые могут отдать что угодно.
2. **Уберите плашку обновлений.** Надёжнее всего — патч нативного `run()` (см. раздел про плашку LiteAPKs): одна инструкция `ret` по смещению `0x8e3a4` в `libieuwh.so`. Если пересобирать APK не хотите, заблокируйте `update.9mod.com` (и остальные серверы мода) на уровне DNS — готовые списки в папке [`blocklists/`](blocklists/) (hosts, AdGuard/uBlock, обычный список доменов для NextDNS).
3. **Ограничьте разрешения**: контакты, геолокацию и «устройства рядом» мод для работы не требует.
4. **Включите двухфакторную защиту** аккаунта TikTok или используйте для мода отдельный аккаунт.
5. Если обход ограничений не нужен — используйте официальное приложение из Google Play.
